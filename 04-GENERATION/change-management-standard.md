# Configuration Change Management

Every material change must be classifiable as:
- add;
- modify;
- remove;
- migrate;
- deprecate.

For each change record:
- reason and affected artifact;
- evidence or project change that triggered it;
- expected behavior change;
- compatibility impact;
- security/permission impact;
- reviewer/approver where required;
- validation performed;
- rollback method.

Never delete user-authored configuration merely because it is not part of the framework's preferred template. Recommend retirement with rationale and wait for approval.
